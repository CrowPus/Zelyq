# Severity and Status

Reserve semantic severity colors for actual states.

Severity and status are different.

Examples of severity:
- critical;
- high;
- medium;
- low;
- informational.

Examples of status:
- open;
- accepted risk;
- fixed;
- verified;
- not reproduced;
- out of scope.

Always include text labels.

Do not use red decoratively across neutral findings.

Order by severity only when severity is the reader's primary decision dimension. Otherwise organize by system, cause, workflow, or chronology.

Security/audit pages should distinguish severity, evidence, affected scope, remediation, and status instead of reducing every issue to a red card.
