# Recipe: Product-Specific Design System

## Input
- product archetype;
- audience;
- brand;
- task density;
- platform;
- accessibility;
- existing constraints.

## Output

### Direction
3–5 keywords + explicit anti-keywords.

### Color
- primitives;
- semantic roles;
- state roles;
- dark/high-contrast strategy if relevant.

### Typography
- families;
- semantic roles;
- numeric/code roles;
- localization fallback.

### Shape / elevation
- radius rhythm;
- borders;
- surface separation;
- shadow/elevation policy.

### Spacing / density
- base rhythm;
- compact/comfortable modes if justified.

### Motion
- functional character;
- duration/easing tokens;
- reduced-motion variant.

### Components
- button hierarchy;
- input treatment;
- navigation;
- surface/card usage;
- feedback.

## Validation
For each major choice ask:
- product fit?
- usability risk?
- accessibility risk?
- performance risk?
- platform fit?
