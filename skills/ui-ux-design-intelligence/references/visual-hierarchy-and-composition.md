# Visual Hierarchy and Composition

## Goal

Make priority visible.

A good interface lets users perceive:
- where to start;
- what matters most;
- which elements belong together;
- what is interactive;
- what is secondary.

## Hierarchy levers

Use intentionally:
- position;
- size;
- weight;
- contrast;
- color;
- whitespace;
- alignment;
- depth;
- repetition.

Do not use all levers at maximum intensity.

## Composition before cards

Start with:
- content blocks;
- alignment relationships;
- grouping;
- reading/scanning path.

Add surfaces/cards only when they communicate:
- grouping;
- containment;
- independent object identity;
- elevation/layer.

Nested cards are often a sign that hierarchy is being outsourced to borders.

## Alignment

Strong alignment creates invisible structure.

Prefer a small number of deliberate alignment axes.

Avoid tiny arbitrary offsets that make the screen feel accidental.

## Whitespace

Whitespace is not "more premium" by default.

Density should match:
- task frequency;
- information volume;
- device;
- expertise;
- brand character.

Operational products often need efficient density. Marketing often needs more pacing.

## Focal points

A screen should rarely have five equally loud actions.

Create a clear primary action only when the workflow genuinely has one.

## Gestalt grouping

Useful perceptual principles:
- proximity;
- similarity;
- common region;
- continuity.

Use them to clarify structure before adding decoration.

## Optical correction

Mathematical centering is not always perceptual centering. Icons, text baselines, and irregular shapes may need optical adjustment.

Do not break token systems casually; document intentional exceptions.

## Review

Squint test:
- what survives first?
- is it what matters?

Grayscale test:
- does hierarchy survive without color?

Content removal test:
- are decorative containers doing work content/layout should do?
