# Spacing, Layout, and Density

## Spacing system

Use a constrained scale to create rhythm.

A scale may be:
- 4-based;
- 8-based;
- mixed;
- product-specific.

Consistency matters more than ideology.

## Semantic spacing

Think in relationships:
- icon-to-label;
- label-to-field;
- field-to-field;
- section-to-section;
- card internal;
- page gutter.

Not every gap of the same pixel value means the same thing.

## Layout

Choose layout from content:
- single column;
- split;
- sidebar + content;
- master-detail;
- grid;
- table;
- canvas/workspace.

Do not choose bento grids before understanding information priority.

## Density

Density should reflect:
- data volume;
- task repetition;
- precision;
- device;
- expertise.

### Comfortable
Good for onboarding, marketing, low-frequency tasks.

### Standard
General application default.

### Compact
Useful for expert/data-heavy workflows.

Do not make compact UIs inaccessible. Target/focus/readability requirements still apply.

## Containers

Use max widths where reading benefits. Let dashboards/workspaces use available width strategically.

## Rhythm

Large spacing should correspond to stronger conceptual separation.

If every section has huge padding, hierarchy flattens.

## Review

- Are related elements visually closer?
- Are major groups separated enough?
- Is density appropriate to task?
- Does whitespace improve comprehension or merely waste space?
