# Content Design

## Principle

Words are interface.

Good UX copy reduces:
- ambiguity;
- memory load;
- anxiety;
- support burden.

## Labels

Use labels that describe the action/result:
- "Create invoice"
- "Send invite"
- "Archive project"

instead of vague:
- "Continue"
- "Proceed"
- "Submit"

when specificity is available.

## Domain language

Use the language users know, not internal database/team terms.

## Errors

Good errors:
1. identify what failed;
2. explain what the user can do;
3. preserve entered work where possible.

Avoid blame.

## Confirmation

Confirmation copy should state consequence.

For destructive actions:
- name the object;
- clarify recoverability;
- distinguish cancel vs destructive action.

## Empty states

An empty state should answer:
- why empty?
- is it expected?
- what can I do next?

Avoid decorative empty-state essays.

## Tone

Tone should fit:
- brand;
- urgency;
- consequence.

Do not use playful copy during serious failure/payment/security situations.

## Inclusion

Apple HIG recommends clear, direct, respectful language and examining assumptions about users.

Avoid unnecessary gender, stereotypes, and culture-specific jokes in global products.

## Review

- Can labels be understood without surrounding context?
- Does copy reveal system terminology?
- Are errors actionable?
- Is tone appropriate to stakes?
