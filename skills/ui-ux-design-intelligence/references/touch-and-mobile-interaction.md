# Touch and Mobile Interaction

## Touch is imprecise

Design for fingers, movement, one-handed use, and interrupted attention.

## Targets

WCAG web minimum target guidance and platform guidelines differ.

Apple commonly recommends comfortable iOS/iPadOS controls around 44×44 pt. Use platform guidance when designing native controls.

## Gestures

Common gestures can accelerate:
- swipe;
- pinch;
- drag.

Do not make essential actions gesture-only when an explicit control can exist.

## Reach and posture

Important frequent actions may benefit from reachable placement, but device size and OS conventions vary.

Avoid rigid "thumb zone" laws as universal truth.

## Keyboards

Mobile software keyboards can cover content. Design:
- visible focused field;
- next/done behavior;
- scroll into view;
- correct input type.

## Interruptions

Preserve draft/progress where feasible.

Mobile users switch apps, lose connectivity, and rotate devices.

## Review

- Can the task be completed one-handed if appropriate?
- Are controls too close?
- Is hover required?
- Does keyboard cover action/error?
