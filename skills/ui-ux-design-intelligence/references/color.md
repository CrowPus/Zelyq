# Color

## Start with roles

Define roles before palette volume:
- background/surface;
- text primary/secondary;
- border;
- action;
- focus;
- success;
- warning;
- danger;
- informational;
- selection.

## Brand vs function

Brand color does not need to carry every semantic function.

A beautiful brand color may fail as:
- text;
- focus indicator;
- destructive state;
- disabled state.

Use accessible functional roles.

## Contrast

For web WCAG 2.2 AA:
- normal text generally requires 4.5:1;
- large text generally 3:1;
- relevant non-text UI/graphical objects often 3:1 under applicable criteria.

Do not use contrast ratios as the only measure of hierarchy/legibility.

## Color alone

Never make color the only carrier of important state.

Add:
- label;
- icon/shape;
- pattern;
- position;
- text.

## Dark mode

Dark mode is not simple inversion.

Review:
- elevation/surfaces;
- muted text;
- borders;
- imagery;
- charts;
- focus;
- saturated colors;
- shadows.

## Data visualization

Categorical palettes need distinguishability and should not rely only on hue for critical comparison.

Sequential data should communicate order.

Diverging data should have meaningful center/reference.

## Cultural meaning

Color meanings vary by locale. Avoid assuming universal semantics outside established product/context conventions.

## Review

- Does every color have a role?
- Is emphasis proportional?
- Does the UI still make sense in grayscale?
- Are status meanings redundant?
- Do dark/light modes preserve hierarchy?
