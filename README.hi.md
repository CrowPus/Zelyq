## Zelyq क्यों

सॉफ़्टवेयर शिप करने के लिए आम तौर पर कई प्रोडक्ट चाहिए: एक AI ऐप बिल्डर, एक सीक्रेट मैनेजर, एक CI
सेवा, एक डिप्लॉय टूल और ऑन-कॉल कोई व्यक्ति। यानी कई लॉगिन, कई बिल और कई जगहें जहां से कोई की लीक
हो सकती है। Zelyq पूरा रास्ता एक प्लेटफ़ॉर्म में रखता है, उसी क्रम में जिसमें काम होता है:

| | मॉड्यूल | यह क्या करता है |
| --- | --- | --- |
| **बनाएं** | **[ऐप](#ऐप)** | किसी ऐप का वर्णन करें। एजेंट उसकी योजना बनाता है, आपकी अपनी असली फ़ाइलों में उसे बनाता है, और पूरा बताने से पहले उसे जांचता है |
| | **[Studio](#studio)** | इमेज और वीडियो बनाएं, आपके ऐप के लिए या अलग से |
| | **[एजेंट](#एजेंट)** | Claude Code, Cursor, VS Code, Gemini CLI या किसी भी MCP क्लाइंट को उसके अपने मॉडल के साथ Zelyq के अंदर काम करने दें |
| **सुरक्षित रखें** | **[Vault](#vault)** | हर क्रेडेंशियल एक बार रखा जाता है, एन्क्रिप्टेड, वर्ज़न के साथ और ऑडिट किया हुआ, और ऐप, पाइपलाइन और आपके अपने सर्वर उसे इस्तेमाल करते हैं |
| **शिप करें** | **[पाइपलाइन](#पाइपलाइन)** | हर बार एक ही तरीके से टेस्ट और बिल्ड करें, Zelyq सर्वर पर या आपकी अपनी Linux, macOS और Windows मशीनों पर |
| | **[डिप्लॉयमेंट](#डिप्लॉयमेंट)** | हर एनवायरनमेंट के लिए ऐप को अपनी मशीनों पर रखें, मंज़ूरी, फ़्रीज़ और अपने आप रोलबैक के साथ |
| | **[Ops](#ops)** | एक AI DevOps इंजीनियर जिससे आप बात कर सकते हैं: यह योजना बनाता है, आपकी मंज़ूरी का इंतज़ार करता है, हर बदलाव साबित करता है और चल रही चीज़ों पर नज़र रखता है |

सब कुछ एक **टीम** का होता है। लोगों को न्योता दें, हर व्यक्ति को एक भूमिका दें, और हर मॉड्यूल उसका
पालन करता है।

## प्लेटफ़ॉर्म

### ऐप

बताएं कि आप क्या चाहते हैं। एजेंट पढ़ता है, योजना बनाता है, फ़ाइलें लिखता है, कमांड चलाता है और एक
लाइव प्रीव्यू शुरू करता है। काम के दौरान आप हर टूल कॉल और हर बदली गई फ़ाइल देख सकते हैं।

- **सिर्फ़ बनाया नहीं, जांचा भी गया।** एजेंट का काम पूरा होने पर Zelyq प्रोजेक्ट का अपना typecheck
  या build चलाता है और जांचता है कि प्रीव्यू क्रैश तो नहीं हो रहा। जिस टर्न ने कुछ तोड़ा, वह पूरा
  बताए जाने के बजाय ठीक करने के लिए एजेंट के पास वापस जाता है।
- **जो जानता है, उसके बारे में साफ़।** *इंजीनियर मोड* जांची गई बातों को अनुमान से अलग रखता है, जो
  विकल्प नहीं चुना उसका नाम बताता है, और पूर्ववत न हो सकने वाले किसी भी काम से पहले पूछता है।
- **बनाने से पहले योजना।** *आर्किटेक्ट मोड* किसी रिक्वेस्ट को ऐसे डिज़ाइन में बदलता है जिसकी आप
  समीक्षा कर सकें (ज़रूरतें, फ़ैसले, डेटा मॉडल, API, बिल्ड प्लान) और आपकी हां का इंतज़ार करता है।
  इसके बाद *ऑटो मोड* उस योजना को एक तय सीमा तक खुद पूरा करता है।
- **विशेषज्ञ हमेशा तैयार।** एक डिज़ाइनर (`DESIGN.md`), एक DevOps इंजीनियर (CI, Dockerfile, डिप्लॉय
  कॉन्फ़िगरेशन), एक सुरक्षा/QA इंजीनियर (टेस्ट और सुरक्षा स्कैन) और एक सिनेमैटिक इंजीनियर (स्क्रॉल के
  साथ चलने वाले पेज)।
- **फ़ुल स्टैक।** React + Vite, Python (FastAPI) बैकएंड वाला React, या Expo React Native, हर एक एक
  डिज़ाइन सिस्टम से शुरू होता है। हर ऑपरेशन के लिए रो-लेवल सुरक्षा के साथ Supabase Postgres।
- **जो पहले से है, वहीं से शुरू करें।** एक GitHub रिपॉज़िटरी इंपोर्ट करें, `/clone <url>` से किसी लाइव
  साइट को फिर से बनाएं, या `/figma <link>` से Figma फ़्रेम और उसके डिज़ाइन टोकन से बनाएं।
- **हर टर्न पूर्ववत हो सकता है।** हर टर्न से पहले एक स्नैपशॉट, ठीक-ठीक क्या बदला इसका diff, और एक क्लिक
  में वापसी। प्रोजेक्ट डिस्क पर सामान्य फ़ाइलें हैं, जिन्हें आप साथ ले जा सकते हैं।

देखें [मोड](./docs/modes.md) और [एजेंट कैसे काम करता है](./docs/agent-behaviour.md)।

### Studio

- **इमेज**: OpenAI, Google या xAI, संदर्भ इमेज और निजी लाइब्रेरी के साथ।
- **वीडियो**: Google Veo या xAI, टेक्स्ट से या किसी स्थिर इमेज से।

Studio आपकी अपनी प्रोवाइडर की इस्तेमाल करता है, जिसका बिल आपके अपने खाते में आता है। किसी प्रोजेक्ट के
लिए इसे चालू करें और एजेंट आपकी तय सीमाओं के भीतर, जिस ऐप को बना रहा है उसके लिए आर्टवर्क और फ़ुटेज बना
सकता है। स्क्रॉल के साथ चलने वाले पेजों के लिए क्लिप को इमेज की श्रृंखला में बांटा जा सकता है। देखें
[Studio: इमेज](./docs/Image-gen/implementation.md) और [Studio: वीडियो](./docs/Video-gen/README.md)।

### एजेंट

वही AI टूल लाएं जो आप पहले से इस्तेमाल करते हैं। एक **एजेंट** Claude Code, Cursor, VS Code, Gemini
CLI, ChatGPT या किसी भी MCP क्लाइंट को उसके अपने मॉडल और सब्सक्रिप्शन के साथ Zelyq के अंदर काम करने देता
है। Zelyq उसे केवल उन्हीं ऐप, पाइपलाइन और एनवायरनमेंट तक पहुंच देता है जिन्हें आप चुनते हैं।

- **एक-एक करके तय की गई अनुमतियां**: बंद, अनुमति है या मंज़ूरी चाहिए, कोड पढ़ने और लिखने, कमांड चलाने,
  पुश, पाइपलाइन, डिप्लॉयमेंट, Studio और भी बहुत कुछ के लिए।
- **ज़रूरी चीज़ें कोई व्यक्ति मंज़ूर करता है।** पुश, पाइपलाइन रन और डिप्लॉयमेंट में बदलाव ऐसी रिक्वेस्ट
  हैं जो इनबॉक्स में इंतज़ार करती हैं।
- **पूर्ववत करना आसान।** एजेंट के किसी ऐप को बदलने से पहले एक अनडू पॉइंट लिया जाता है।
- **सीक्रेट के मान कभी नहीं दिखते।** एजेंट केवल नाम से देखता है कि किसी ऐप को कौन-से सीक्रेट मिलते हैं।

देखें [एजेंट](./docs/agents.md)।

### Vault

हर क्रेडेंशियल **एक बार** रखें और उसे हर जगह इस्तेमाल करें, किसी फ़ाइल में चिपकाए बिना।

- **स्टोरेज में एन्क्रिप्टेड** (AES-256-GCM), **वर्ज़न हिस्ट्री**, लाइव की के लिए **सुरक्षित** का निशान,
  और हर बार दिखाने और बदलने का रिकॉर्ड।
- **रेफ़रेंस से इस्तेमाल।** ऐप वेरिएबल, मॉडल की, पाइपलाइन और एनवायरनमेंट `vault://NAME` की ओर इशारा
  करते हैं। मान केवल वहीं और तभी भरा जाता है जहां और जब ज़रूरत हो।
- **लॉग में छिपा हुआ।** पाइपलाइन लॉग तक पहुंचने वाला सीक्रेट `***` के रूप में दिखता है।
- **आपके अपने सर्वर के लिए भी।** सीमित सर्विस की से सीक्रेट लें, या `zelyq vault run -- <command>`
  चलाकर उनके साथ कोई प्रोसेस शुरू करें, डिस्क पर कुछ लिखे बिना।
- **`.env` इंपोर्ट करके आसानी से आएं।**

देखें [Vault](./docs/vault.md)।

### पाइपलाइन

पाइपलाइन एक छोटी YAML फ़ाइल है, या एक चित्र जिसे आप क्लिक करके एडिट करते हैं। स्टेज क्रम से चलते हैं,
स्टेप भी क्रम से चलते हैं, और हर स्टेप एक कमांड या एक तैयार ब्लॉक होता है।

```yaml
name: Shop
runs-on: local                      # the Zelyq server, or one of your machines
source: { app: Shop }
stages:
  - name: Test
    matrix: { node: [20, 22] }      # one copy per version, at the same time
    steps:
      - checkout: true
      - setup: node@${{ matrix.node }}
      - run: npm ci && npm test
        tests: reports/*.xml        # JUnit: passed / failed on the step
  - name: Deploy
    steps:
      - deploy: { to: production, port: 3000 }
```

- **जहां आप चुनें, वहां चलती है।** Zelyq सर्वर पर एक बार इस्तेमाल होने वाले कंटेनर में, या आपकी अपनी
  **Linux, macOS और Windows** मशीनों पर। एक मशीन एक ही इंस्टॉल कमांड से जुड़ जाती है और HTTPS पर
  खुद Zelyq से कनेक्ट होती है, किसी पोर्ट को खोले बिना। SSH से जुड़ी मशीनें भी समर्थित हैं।
- **तेज़ और लचीली।** एक साथ चलने वाले स्टेज, हर स्टेज के लिए अलग मशीन, मैट्रिक्स बिल्ड और पाइपलाइनों में
  साझा टेम्पलेट।
- **प्लगइन।** किसी स्टेप को एक बार पैक करें, इनपुट, Vault के सीक्रेट और आउटपुट के साथ, फिर उसे किसी भी
  पाइपलाइन में इस्तेमाल करें। देखें [पाइपलाइन प्लगइन](./docs/pipeline-plugins.md)।
- **किसी भी चीज़ से शुरू।** हाथ से, git push से (पाथ फ़िल्टर के साथ), पुल रिक्वेस्ट से, शेड्यूल से, किसी
  दूसरी पाइपलाइन के पूरा होने पर, एजेंट के ऐप बदलने पर, या सर्विस की वाली किसी भी CI से।
- **असली पाइपलाइन को जो चाहिए, सब।** टूल सेटअप और कैश, सर्विस कंटेनर (Postgres, Redis), स्टेप
  आउटपुट, JUnit रिपोर्ट, आर्टिफ़ैक्ट, मंज़ूरी, दोबारा कोशिश, टाइमआउट और एक साथ चलने पर नियंत्रण।
- **नतीजा वापस बताती है।** GitHub या GitLab में कमिट और पुल रिक्वेस्ट पर ✓ / ✗।

देखें [पाइपलाइन](./docs/pipelines.md)।

### डिप्लॉयमेंट

- **एनवायरनमेंट** जैसे `staging` और `production`, हर एक आपकी किसी मशीन पर, हर एक के अपने वेरिएबल।
  staging पर टेस्ट की और production पर लाइव की, दोनों Vault से।
- **पाइपलाइन से डिप्लॉय करें**, ताकि शिप होने से पहले ऐप टेस्ट हो जाए। Zelyq आपकी मशीन पर इमेज बनाता है,
  ऐप के `Dockerfile` से या उस Dockerfile से जो वह Node, Python, Go और स्टैटिक साइटों के लिए लिखता है।
  किसी रजिस्ट्री की ज़रूरत नहीं।
- **अपने आप रोलबैक।** अगर नया वर्ज़न अपने हेल्थ चेक में विफल होता है, तो पिछला वर्ज़न अपने आप वापस आ
  जाता है।
- **HTTPS के साथ आपका अपना डोमेन**, वर्ज़न के बीच बिना डाउनटाइम।
- **लाइव लॉग, CPU और मेमोरी**, रीस्टार्ट और रोकना, और एक क्लिक में किसी पिछले वर्ज़न पर रोलबैक।
- **प्रमोट करें**: staging पर टेस्ट हुई वही इमेज production पर ले जाएं, दोबारा बिल्ड किए बिना।
- **सुरक्षित एनवायरनमेंट** एडमिन की मंज़ूरी का इंतज़ार करते हैं। **फ़्रीज़** रिलीज़ के दौरान सारे डिप्लॉय
  रोक देता है।

देखें [डिप्लॉय](./docs/deploy.md)।

### Ops

**Ops** टीम का DevOps इंजीनियर है। उससे लिखकर या बोलकर कहें कि कोई ऐप ऑनलाइन करे, नया वर्ज़न शिप करे,
डोमेन सेट करे, या बताए कि कुछ धीमा क्यों है।

- **पहले देखता है और योजना दिखाता है।** Ops बेझिझक देखता है, लेकिन हर बदलाव सटीक स्टेप की एक सूची है
  जो आपकी मंज़ूरी का इंतज़ार करती है। जो स्टेप पूर्ववत नहीं हो सकता, उसे अलग से पक्का किया जाता है।
- **हर बदलाव साबित करता है।** Zelyq नतीजा खुद जांचता है। कोई स्टेप तभी पूरा माना जाता है जब उसकी जांच
  पास हो।
- **कभी निगरानी नहीं छोड़ता।** वेबसाइट और ऐप हर मिनट जांचे जाते हैं, मशीनें हर पांच मिनट, सर्टिफ़िकेट और
  डोमेन हर दिन, किसी मॉडल के बिना। अलर्ट ईमेल, Telegram, Slack या Discord से आप तक पहुंचते हैं।
- **केवल वही जो आप सौंपें।** एक एडमिन उसे एनवायरनमेंट, मशीनें, पाइपलाइन और कोड एक-एक करके देता है, हर
  एक के लिए भरोसे के स्तर के साथ। यह सीक्रेट के नाम देखता है, उनके मान कभी नहीं।
- **याद रखता है।** आपके दिए नियम और गड़बड़ियों से मिले सबक रखे जाते हैं और हर काम से पहले पढ़े जाते हैं।
- **नियंत्रण आपके हाथ में।** मासिक खर्च की सीमा, और **Ops रोकें** सब कुछ तुरंत रोक देता है।

## टीमें, प्लान और भाषाएं

| भूमिका | क्या कर सकते हैं |
| --- | --- |
| `viewer` | ऐप, फ़ाइलें, रन, एनवायरनमेंट और डिप्लॉय हिस्ट्री देखना |
| `editor` | ऊपर का सब, साथ ही एजेंट को काम देना, पाइपलाइन चलाना और डिप्लॉय करना |
| `admin` | ऊपर का सब, साथ ही सदस्य, एजेंट, एनवायरनमेंट, मंज़ूरियां और सुरक्षित सीक्रेट |
| `owner` | पूरा नियंत्रण, टीम समेत |

- **गतिविधि।** हर बदलाव टीम की गतिविधि में दर्ज होता है: दिखाया गया सीक्रेट, एडिट की गई पाइपलाइन,
  रोलबैक किया गया डिप्लॉय।
- **प्लान और इस्तेमाल।** हर टीम के लिए ऐप, स्टोरेज, पाइपलाइन रन, सदस्यों और प्रीव्यू की सीमाएं होती हैं,
  जिन्हें सर्वर का एडमिन तय करता है।
- **दूसरों के लिए Zelyq चलाना।** [मैनेज्ड मोड](./docs/managed-mode.md) साइन-इन को आपकी अपनी खाता सेवा के
  पीछे रखता है, और [एडमिन API](./docs/admin-api.md) से आपके सिस्टम लोगों, टीमों, प्लान और सेहत को
  मैनेज करते हैं।
- **नौ भाषाएं।** इंटरफ़ेस और उसकी बिल्ट-इन मदद अंग्रेज़ी, फ़्रेंच, जर्मन, स्पैनिश, पुर्तगाली, चीनी, हिन्दी,
  इतालवी और जापानी में है, हर व्यक्ति अपनी भाषा चुन सकता है।
- **निष्क्रिय ऐप सो जाते हैं।** जिन ऐप को कुछ समय से किसी ने नहीं खोला, वे S3-संगत बकेट या किसी फ़ोल्डर
  में जा सकते हैं, और खोलने पर अपने आप जाग जाते हैं। देखें [स्टोरेज](./docs/storage.md)।

## तुरंत शुरुआत

**सबसे तेज़ तरीका:** **[app.zelyq.dev](https://app.zelyq.dev)** पर खाता बनाएं। एक मुफ़्त प्लान है, और
कुछ भी इंस्टॉल नहीं करना।

**इसे खुद चलाने के लिए:**

```bash
# Requires Node >= 20.12 and pnpm >= 9
git clone https://github.com/CrowPus/Zelyq.git
cd Zelyq
cp .env.example .env    # your configuration: check it before the first start (below)
pnpm install
pnpm dev                # web :5173 · server :8787 · agent :8788
```

<http://localhost:5173> खोलें और पहला खाता बनाएं। वही खाता इंस्टेंस का एडमिन होता है। **सेटिंग → मॉडल**
में अपने मॉडल की की जोड़ें (टाइप करके या Vault से), **ऐप** खोलें, एक ऐप बनाएं और बताएं कि आप क्या चाहते
हैं।

**VM या रिमोट सर्वर पर**, पहली बार शुरू करने से पहले `.env` में ये बदलें। `203.0.113.10` की जगह अपनी
मशीन का पता या डोमेन लिखें:

| सेटिंग | मान | क्यों |
| --- | --- | --- |
| `ZELYQ_WEB_HOST` | `0.0.0.0` | नहीं तो इंटरफ़ेस केवल उसी मशीन पर जवाब देता है |
| `ZELYQ_PREVIEW_HOST` | `203.0.113.10` | नहीं तो ऐप प्रीव्यू आपका ब्राउज़र स्वीकार नहीं करते |
| `ZELYQ_CORS_ORIGIN` | `http://203.0.113.10:5173` | वह पता जिस पर आप Zelyq खोलते हैं |
| `ZELYQ_PUBLIC_URL` | `http://203.0.113.10:5173` | webhook और साइन-इन लिंक में इस्तेमाल होता है |
| `ZELYQ_ALLOW_REGISTRATION` | आपका खाता बन जाने के बाद `false` | नहीं तो पता ढूंढने वाला कोई भी साइन अप कर सकता है |

फ़ायरवॉल में पोर्ट 5173 और प्रीव्यू पोर्ट (`ZELYQ_PREVIEW_PORT_MIN`–`MAX`, डिफ़ॉल्ट 4300–4399) खोलें।
इंटरनेट से पहुंचने लायक मशीन पर Zelyq को HTTPS के पीछे रखें: देखें [सेल्फ़-होस्टिंग](./docs/self-hosting.md)।
बाकी हर सेटिंग `.env.example` और [कॉन्फ़िगरेशन](./docs/configuration.md) में समझाई गई है।

**Docker के साथ:** `docker compose -f docker/docker-compose.yml up`। देखें
[सेल्फ़-होस्टिंग](./docs/self-hosting.md)।

**आगे:** [ट्यूटोरियल](./docs/tutorial.md) किसी ऐप को कदम-दर-कदम Zelyq से प्रोडक्शन तक ले जाता है: Vault,
एक पाइपलाइन, आपकी अपनी मशीन, रोलबैक के साथ एक डिप्लॉय, और GitHub पुश और पुल रिक्वेस्ट।

### अपडेट करना

आपका डेटा वहीं रहता है जहां है। डेटाबेस, बनाया गया मीडिया और एन्क्रिप्शन की `data/` में हैं, आपके ऐप
`workspace/` में और आपकी सेटिंग `.env` में। Git तीनों को अनदेखा करता है, और सर्वर शुरू होते समय डेटाबेस
के बदलाव खुद लागू करता है।

```bash
cd ~/Zelyq                                    # wherever you cloned it
# 1. Stop Zelyq (Ctrl+C if it runs as `pnpm dev`)

# 2. Back up first
cp -a data ~/zelyq-data-backup-$(date +%F)
cp -a workspace ~/zelyq-workspace-backup-$(date +%F) 2>/dev/null
cp .env ~/zelyq-env-backup-$(date +%F) 2>/dev/null

# 3. Get the new version and rebuild
git pull
pnpm install
pnpm build

# 4. Start Zelyq again the same way as before
```

ये कमांड उसी उपयोगकर्ता से चलाएं जिसने Zelyq क्लोन किया था। अगर Git `detected dubious ownership` पर
रुक जाए, तो `safe.directory` अपवाद जोड़ने के बजाय `su - <user>` से उस उपयोगकर्ता पर जाएं।

Docker के साथ: `git pull`, फिर `docker compose -f docker/docker-compose.yml up -d --build`। आपका डेटा
`zelyq-data` वॉल्यूम में है, इसलिए `docker compose down -v` **कभी** न चलाएं, यह उसे हटा देता है।

ज़्यादा जानकारी, PostgreSQL समेत: [सेल्फ़-होस्टिंग → अपग्रेड](./docs/self-hosting.md#upgrading)।

## यह कैसे काम करता है

तीन प्रोसेस और एक कमांड-लाइन टूल, चार साझा लाइब्रेरी पर बने हुए। किसी ऐप की फ़ाइलों और कमांड तक केवल
एक रास्ते से पहुंचा जाता है, `RuntimeDriver`, और इसी से लोकल, कंटेनर और रिमोट होस्ट एक जैसे काम करते
हैं।

```
   Browser                                 zelyq CLI  (zelyq vault run …)
      │                                        │
      │  REST + WebSocket                      │  HTTPS, service key
      ▼                                        ▼
 ┌──────────────────────────────────────────────────────────┐
 │ apps/server   Fastify · owns the database                │
 │ teams · apps · Vault · pipelines · deploys · Ops         │
 └────┬───────────────────────┬─────────────────────┬───────┘
      │ HTTP + SSE            │                     │ outgoing HTTPS or SSH
      ▼                       │                     ▼
 ┌──────────────┐             │             ┌────────────────────────────┐
 │ apps/agent   │             │             │ Runners and environments   │
 │ model loop,  │             │             │ your Linux, macOS, Windows │
 │ tools        │             │             │ machines: pipelines,deploys│
 └──────┬───────┘             │             └────────────────────────────┘
        │                     │  files, previews, snapshots
        ▼                     ▼
 ┌──────────────────────────────────────────────────────────┐
 │ RuntimeDriver   the only path to disk and shell          │
 │ local · container (one per project) · remote host        │
 └──────────────────────────────────────────────────────────┘
```

| हिस्सा | ज़िम्मेदारी |
| --- | --- |
| [`apps/web`](./apps/web) | इंटरफ़ेस: चैट, एडिटर और प्रीव्यू, Studio, Vault, पाइपलाइन, डिप्लॉयमेंट, Ops |
| [`apps/server`](./apps/server) | टीमें, ऐप, Vault, पाइपलाइन इंजन, डिप्लॉय और Ops; डेटाबेस से बात करने वाला एकमात्र प्रोसेस |
| [`apps/agent`](./apps/agent) | मॉडल लूप। यह खुद कभी फ़ाइलें नहीं छूता: हर टूल `RuntimeDriver` से होकर जाता है |
| [`apps/runner`](./apps/runner) | आपकी मशीनों पर इंस्टॉल रनर; यह Zelyq से जुड़ता है और पाइपलाइन और डिप्लॉय चलाता है |
| [`apps/cli`](./apps/cli) | `zelyq` कमांड लाइन, जैसे `zelyq vault run` |
| [`apps/registry`](./apps/registry) | साइन किए गए प्लगइन की रजिस्ट्री |
| [`@zelyq/core`](./packages/core) | डोमेन टाइप, पाइपलाइन फ़ाइल का फ़ॉर्मैट और प्रोटोकॉल |
| [`@zelyq/runtime`](./packages/runtime) | `RuntimeDriver` और उसके इम्प्लीमेंटेशन; प्रोसेस शुरू करने वाला एकमात्र कोड |
| [`@zelyq/db`](./packages/db) | Drizzle स्कीमा और माइग्रेशन: डिफ़ॉल्ट रूप से SQLite, बढ़ने पर PostgreSQL |
| [`@zelyq/tools`](./packages/tools) | एजेंट के टूल, `RuntimeDriver` के लिए एक बार लिखे गए |

पूरी जानकारी: [आर्किटेक्चर](./docs/architecture.md)।

## सुरक्षा

Zelyq जांचे जाने के लिए बना है: सरल स्टोरेज, सामान्य फ़ाइलें, कोई टेलीमेट्री नहीं, और सीक्रेट जो स्टोरेज में
एन्क्रिप्टेड रहते हैं और कभी कमांड लाइन या लॉग में नहीं जाते। डिप्लॉय करने से पहले ये सीमाएं जान लें:

- **`local` रनटाइम मोड सैंडबॉक्स नहीं है।** एजेंट की कमांड सर्वर के उपयोगकर्ता के रूप में चलती हैं। इसे
  एक मशीन पर एक भरोसेमंद डेवलपर के लिए इस्तेमाल करें। किसी भी साझा या इंटरनेट से जुड़े इस्तेमाल के
  लिए `ZELYQ_RUNTIME=container` सेट करें।
- **कंटेनर मोड का बाहर जाने वाला नेटवर्क डिफ़ॉल्ट रूप से खुला है।** यह हमेशा क्लाउड मेटाडेटा एंडपॉइंट और
  प्रोजेक्ट के बीच के ट्रैफ़िक को रोकता है। बाकी को सीमित करने के लिए `ZELYQ_CONTAINER_EGRESS_ALLOWLIST`
  सेट करें, या भरोसे से बाहर के कोड के लिए [सख़्त सैंडबॉक्स](./docs/strict-sandbox.md) इस्तेमाल करें।

डिप्लॉय करने से पहले [थ्रेट मॉडल](./SECURITY.md#threat-model--read-this-before-deploying) पढ़ें, और
[SECURITY.md](./SECURITY.md) में बताए अनुसार कमज़ोरियों की निजी रूप से रिपोर्ट करें।

रिपॉज़िटरी की बनावट और कोई बदलाव आम तौर पर कहां जाता है, यह बताया गया है। पुल रिक्वेस्ट खोलने से पहले
`pnpm lint`, `pnpm typecheck` और `pnpm test` चलाएं। हिस्सा लेने वाले सभी लोग
[आचार संहिता](./CODE_OF_CONDUCT.md) का पालन करते हैं।
